# V4 Benchmark Baseline

This is a reproducible microbenchmark baseline, not a production capacity claim.

## Environment

- Date: 2026-08-23
- Go: 1.26.4
- OS/architecture: windows/amd64
- CPU: 11th Gen Intel(R) Core(TM) i7-11800H @ 2.30GHz
- Logical benchmark workers: 16 (GOMAXPROCS)
- Samples: 5 per case; the table reports the median

## Method

```bash
go test -run '^$' \
  -bench '^Benchmark(Router|ProviderConcurrencyLimiter|GatewayMock)' \
  -benchmem -count=5 \
  ./internal/routing ./internal/concurrency ./internal/service
```

- Router uses three always-available in-process targets. Round Robin weights are 1:1:1; smooth Weighted Round Robin weights are 5:3:2.
- Provider concurrency limiter measures acquire/release on a channel semaphore with capacity 64.
- Gateway measures a validated non-streaming request through GatewayService and the deterministic Mock Provider. Redis, PostgreSQL, HTTP serialization, and network I/O are intentionally excluded.
- Serial cases use one testing.B loop. Parallel cases use RunParallel, which created 16 workers on this machine.

## Median results

| Case | Workers | ns/op | B/op | allocs/op |
|---|---:|---:|---:|---:|
| Router / Round Robin | 1 | 64.09 | 128 | 1 |
| Router / Weighted Round Robin | 1 | 83.69 | 128 | 1 |
| Router / Round Robin | 16 | 133.6 | 128 | 1 |
| Router / Weighted Round Robin | 16 | 135.3 | 128 | 1 |
| Provider concurrency limiter | 1 | 76.98 | 24 | 1 |
| Provider concurrency limiter | 16 | 115.2 | 24 | 1 |
| Gateway + Mock Provider | 1 | 1,747 | 1,017 | 12 |
| Gateway + Mock Provider | 16 | 617.0 | 1,021 | 12 |

Parallel ns/op is aggregate wall-clock time per operation, so it can be lower than the serial value when independent work scales across cores. Router contention moves in the opposite direction because target selection deliberately serializes mutable scheduling state behind one mutex.

Real Redis/PostgreSQL tests in V4 validate behavior, atomic Lua execution, migrations, transactions, and HTTP policy composition. They are not used to publish latency or throughput numbers because this workstation did not have a local container runtime. Run the same command on the target deployment hardware before making performance decisions.
